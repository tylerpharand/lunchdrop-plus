## What this project is

**Lunchdrop+** is a browser extension for [Lunchdrop](https://www.lunchdrop.com/). The repo is **lunchdrop-plus**.

Lunchdrop stays the ordering surface. We do not build our own cart, checkout, or payment flow.

The extension saves a support-fee preference and, after Lunchdrop places an order, posts that fee when it differs from Lunchdrop's default. The preference is Lunchdrop's default, a percentage of the meal, the subsidy left after this meal takes its share of the cap, or none ($0). A meal that costs at least the cap leaves nothing for support. The popup is where that preference is saved. On an open order, the support row is labeled "Support:". When the amount is not Lunchdrop's own fee, that price is bold and italic, with an accent-green lightning bolt to its left. A support amount of $0.00 keeps that styling unless Custom is selected for that order. Clicking the price opens a modal with Custom, Percentage, Remaining subsidy, and None. Custom is a dollar amount for this order. It starts at Lunchdrop's fee from the latest place, item update, or item removal response, and otherwise at the amount on the receipt. Editing or removing an item replaces that saved fee and applies the preference again. Percentage, Remaining subsidy, and None update the order as soon as they are picked. Remember for future orders appears for those three. It starts checked when that choice is already saved. Picking Percentage, Remaining subsidy, or None checks it and saves that choice, unless the user has unchecked it. The order keeps that choice when the dollar amount does not change, so Remaining subsidy at $0 stays selected after None. Custom is not remembered. A spinner grows in on the row under that price while the request runs, then a checkmark fades out. The option text keeps its width. The popup is headed Lunchdrop+ in bold accent green, with the extension version in grey parentheses beside it, and groups settings into Support and UI tabs. A subdued GitHub mark at the right of that heading opens the public repository. Support is the fee preference. UI chooses hide all, show all, or a custom mix of reminders, ratings, referrals, and invites. Those start hidden. Order updates stay visible. The order summary links to add more items, enter a promo code or gift card, and remove the subsidy, plus the info icons beside each breakdown row, start hidden, with the same hide-all, show-all, or custom choice. Cancel stays visible. Long words in item descriptions wrap onto the next line, on by default, and the UI tab can turn that off. Restaurant cards grow so a full row lines up with the page. A short last row stays the same card size and stays on the left. That layout is on by default, and the UI tab can turn it off. Enhanced restaurant tiles start on, and the UI tab can turn them off. They hide the delivery time and the order deadline under each restaurant, tighten the gap between those tiles, and drop a tile's bottom padding when nothing is left under the logo. An order already placed turns that tile dark green (#006400). The logo shrinks to leave an accent-green chin with a white checkmark and Order Placed. The chin is painted on the tile itself so the dark green cannot show through a seam. When that tile is selected, its offset border is accent green (#009900) with 12px corners, the way other selected tiles keep their border off the tile. Enhanced tiles round every selected tile's border to 12px. The green New badge on a restaurant tile stays visible until the UI tab hides it. Improved menu bar starts on. The date picker stays at the top in place of the header. Days fade out at the left and right of the scroller, the menu button sits on the left fade, and the calendar button stays off. The selected day keeps white text, a 3px white border at 60% opacity, and a white fill from 25% at the top to 15% at the bottom. The day scroller only moves sideways. On a narrow screen, the bar scales to 90% so the text, padding, and height are a little smaller, and it still spans the width. A 1px bottom border in black at 12.5% opacity (#00000020) separates the bar from what sits under it. One-step sign in starts off. The UI tab can turn it on. The sign-in page then shows the email and password together, so a password manager can fill both. A blank password still continues to company sign-in. The on-page support sheet stays on the visible viewport while the page scrolls and while the browser chrome collapses. A narrow viewport keeps the sheet on the bottom edge. A wider viewport centers it.

Menu alerts live in a separate project. This extension works with no account on that service.

## Conventions

- Yarn, not npm.
- The extension must work with no account on the notification service.
- `yarn verify` runs ESLint, Prettier, and `tsc --noEmit`. It must pass. The script is `verify` because Yarn 1 treats `yarn check` as its own command.
- ESLint is typescript-eslint `strictTypeChecked` and `stylisticTypeChecked`, plus the React and React Hooks recommended configs (including the compiler rules). Extra bans: `any` is already an error, non-null assertions, `ts-ignore`, `ts-nocheck`, and `console.log`. `console.warn` and `console.error` are allowed. Exported functions need return types.
- TypeScript, on top of the WXT baseline (`strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`): `exactOptionalPropertyTypes`, `noPropertyAccessFromIndexSignature`, `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns`, `noUncheckedSideEffectImports`, `erasableSyntaxOnly`.
- Prettier: no semicolons, single quotes, trailing commas where ES5 allows, 100-column lines.
- `yarn install` installs a pre-commit hook (lint-staged) and a pre-push hook (`yarn verify`). ESLint stays on v9 until `eslint-plugin-react` supports v10.
- `yarn release 0.1.0` (or `patch`, `minor`, `major`) verifies, zips Chrome and Firefox, commits the version bump, and publishes the Chrome zip to GitHub release `v0.1.0`. That zip does not auto-update. The Firefox zip is a build check and is not published. Chrome and Arc update from the Chrome Web Store, including an unlisted listing. Publishing the release runs `.github/workflows/firefox-amo.yml`, which submits the Firefox build to addons.mozilla.org on the unlisted channel and attaches the signed package as `lunchdrop-plus-0.1.0-firefox.xpi`. That file installs on desktop Firefox and Firefox for Android. The workflow needs repository secrets `WEB_EXT_API_KEY` and `WEB_EXT_API_SECRET` from the [add-on API key page](https://addons.mozilla.org/developers/addon/api/key/).
